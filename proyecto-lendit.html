Plataforma de préstamo colaborativo para comunidades cerradas — edificios, barrios, coworks, universidades. El diseño no resuelve cómo encontrar usuarios: resuelve cómo organizar los recursos que ya existen entre personas que ya se conocen.

El problema no es encontrar usuarios

En edificios, barrios privados, universidades y espacios de coworking hay objetos que se prestan constantemente. Pero ese intercambio se gestiona de forma informal: un mensaje en el grupo de WhatsApp, una planilla compartida que nadie actualiza, un acuerdo de palabra que depende de la memoria de todos.

El problema no es que falten recursos — es que no hay una herramienta pensada para administrarlos. La confianza entre los miembros ya existe. Lo que falta es la infraestructura que la soporte.

No es un marketplace — es una comunidad

Wallapop y Getaround resuelven transacciones entre desconocidos. LendIt parte de un punto completamente distinto: los usuarios ya se conocen, ya comparten un espacio físico, y la confianza ya existe. El desafío no era construirla desde cero — era no destruirla con una experiencia mal diseñada.

El sistema se organiza en grupos cerrados y moderados. Cada comunidad tiene su propio administrador, sus recursos visibles y su historial de préstamos. Los roles de usuario permiten adaptar la plataforma a contextos muy distintos: el encargado de un edificio tiene necesidades diferentes a las de una biblioteca universitaria o al coordinador de un cowork.

"El desafío no era construir confianza desde cero. Era no destruir la que ya existía."

— Principio de diseño · LendIt

El proceso

El proyecto no buscaba construir un MVP técnico inmediato. El objetivo era explorar cómo una experiencia digital podría optimizar la gestión de recursos compartidos dentro de comunidades locales — y para eso, el diseño necesitaba entender primero esos contextos.

Se construyeron user personas y user stories a partir de tres perfiles concretos: administradores de edificios, vecinos de barrios cerrados y encargados de instituciones educativas. Cada perfil tenía necesidades distintas pero compartía un mismo problema central: gestionar préstamos sin ninguna herramienta pensada para eso.

El resultado es un sistema con grupos cerrados, administración comunitaria, visibilidad de recursos e historial de préstamos — diseñado específicamente para contextos donde el problema no es encontrar usuarios, sino organizar eficientemente lo que ya existe entre ellos.
