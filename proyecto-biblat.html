Biblat

API REST pública y gratuita de literatura latinoamericana. Libros, autores y categorías de siete países, con búsqueda full-text en español, documentación Swagger y backoffice de administración. Construida porque no existía ninguna.

El problema era la ausencia

Existen grandes bases de datos de libros — Open Library, Google Books, Goodreads — pero ninguna pensada para quien necesita consumir datos de literatura latinoamericana de forma programática, en español, sin fricciones y sin costo. No hay una API REST pública y regional para ese caso de uso.

Biblat resuelve esa ausencia. Es una API de solo lectura, gratuita y sin autenticación para el consumidor, que cubre siete literaturas nacionales: argentina, mexicana, colombiana, uruguaya, chilena, peruana y latinoamericana en general.

Cómo funciona

Los datos se obtienen de Open Library mediante un scraper automatizado que consulta siete subjects regionales y los almacena en PostgreSQL vía Supabase. El scraper respeta un intervalo de 1000ms entre requests para no saturar la fuente.

La API expone endpoints de solo lectura para cualquier consumidor: listar libros paginados, buscar por título o autor con full-text en español —indexado con GIN en PostgreSQL—, filtrar por categoría, ISBN o autor, y consultar listas de autores y categorías únicos. Las operaciones de escritura requieren API key y son exclusivas del backoffice de administración.

"El primer paso fue constatar que no existía nada parecido. El segundo fue construirlo."

— Biblat · API de literatura latinoamericana

Stack y arquitectura

Backend en Node.js con Express, base de datos PostgreSQL vía Supabase, documentación generada con Swagger UI en /docs, y rate limiting con express-rate-limit para proteger el servicio. El backoffice es HTML + CSS + JS vanilla, sin frameworks.

La API está desplegada en Railway. El backoffice corre en Vercel. La respuesta sigue una estructura consistente en todos los endpoints: { data, meta } para listas y { error, code } para errores.
